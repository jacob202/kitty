## Summary

Black-box operational acceptance audit of the KittyBuilder core execution control plane against a clean main (isolated worktree, deterministic local fixtures, no provider/network/model calls). **Verdict: FAIL** — one defect found and fixed in this PR.

## The defect (BUG-1)

A worker that dies mid-run (SIGKILL) while the supervisor survives closes its attempt as failed and the loop retries **in-process**. The dirty worktree re-enters `ensure_worktree`, which refuses dirty trees, so the retry closes `crashed` (`infrastructure_failed`, phase `worker_orchestration`) and the packet deadlocks forever. Afterward **no supported command recovers it**: `queue recover` reports zeros, `clean-worktree` refuses dirty, `operator-release` rejects a queued task, `archive` targets terminal states — only manual `git` surgery escapes.

P027 (#196) fixed the dead-supervisor path via `archive_and_reset_worktree` in `_reconcile_stale_attempts`, but the live-loop retry path was never wired up.

## Fix

In `run_packet`, on the in-process retry (`attempt_no > 1`), archive the prior failed attempt's dirty worktree into its artifact dir (`crashed-worktree.patch` + `crashed-worktree-status.txt`), then reset — mirroring P027. `archive_and_reset_worktree` is a no-op for clean/missing trees, so the change is safe for ordinary retries.
