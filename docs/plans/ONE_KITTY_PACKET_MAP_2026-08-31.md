# ONE KITTY — Packet Map

## Phase 0 — integrate incoming WOW foundations

Do not implement ONE KITTY on an obsolete baseline.

Required accepted equivalents before code starts:
- Capability Launcher
- Artifact Canvas
- Activity Center
- Project Workspace
- Rich Chat durable action/artifact cards
- Context Picker
- Personal Intelligence
- Research Workspace
- Image Studio where its active lane settles

These are not ONE KITTY dependencies because their exact feature set is sacred; they are dependencies because ONE KITTY deliberately reuses their authorities/projections/components instead of duplicating them.

# Collision guidance

High-collision shared files likely include:
- `gateway/kitty-chat/src/lib/gateway.ts`
- `gateway/kitty-chat/src/lib/queries.ts`
- `gateway/kitty-chat/src/app/page.tsx`
- `ChatMessage.tsx`
- `InputBar.tsx`
- `HomeState.tsx`
- `HomeView.tsx`
- `globals.css`
- route registration
- context assembler

Treat these as sequential ownership lanes.

Lower-collision work suitable for parallel agents after contracts settle:
- domain adapters;
- isolated visual surface migrations;
- test/acceptance harnesses;
- brand asset/component implementation after spec;
- copy/empty-state cleanup in disjoint components.

# Campaign exit statement

Kitty is done with ONE KITTY when it behaves like one product: Chat can understand and guide across canonical Kitty objects; Home is prioritized and actionable; an object's identity/truth survives surface changes; interactions visibly resolve; visual geometry is precise; and Kitty has a restrained recognizable character without sacrificing calm utility.
