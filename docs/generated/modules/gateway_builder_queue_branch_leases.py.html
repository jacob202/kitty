Overview

Builder queue branch leases — packet/worker/branch/worktree exclusive leases. Extracted from :mod:`gateway.builder_queue` as the fourth cut of audit §2.2 (the order has been DB §1, lease lifecycle §2, run lifecycle §3, branch leases §4, events/PRs §5 — split earlier in builder_queue.py so each cut owns a coherent lifecycle). Owns the ``KB-S2 atomic claim_and_start_attempt`` support: an exclusive lease keyed by ``(initiative_id, packet_id, worker_id, branch, worktree_path)`` with initiative_id scoping so v1/v2 retries of the same packet from different initiatives can coexist. ``claim_branch_lease`` inserts with a unique-index guarantee; ``verify_branch_lease`` reads back; ``release_branch_lease`` does an owner-fenced delete. The two ``on_conn`` variants let sibling code (``gateway.builder_attempt`` and ``gateway.builder_identity``) participate in the caller's transaction for atomic packet-launch plumbing. Public symbols are re-exported from :mod:`gateway.builder_queue` via the façade so callers (``gateway.builder_attempt``, ``gateway.builder_identity``, ``gateway.builder_loop``, CLI, tests) work unchanged. Active-mission note (:file:`.claude/STATE.md`): the chat-recovery work ``CR-02-thread-goals-ui`` is independent of this module. Dependency resolution: this module imports from ``gateway.builder_queue_db`` only (no parent↔child cycle with ``gateway.builder_queue``). The branch-lease lifecycle never calls ``append_event`` or ``_apply_transition`` — every operation here is purely SQL on the ``branch_leases`` table — so the simple top-level import of :mod:`gateway.builder_queue_db` is safe.
