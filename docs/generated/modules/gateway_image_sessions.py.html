Overview

Durable conversational image sessions (issue #336, slice A1). Image Studio could render an image but could not remember one. Each request started from form state, so "keep his face, make his build broader" had nothing to refer back to. This module stores the conversation: what the subject is, which result is selected, what must not change, and what was asked for. Boundaries: - This module owns session state only. ``image_jobs`` remains the record of what was rendered, and ``image_runner`` remains the only dispatch path. Nothing here submits work to a renderer. - The anchor is the selected result a follow-up operates on. Only a succeeded job carrying a verified artifact may become one — an anchor that cannot be fed to a renderer is worse than no anchor, because it fails at render time instead of selection time. - Every mutation validates and raises. There are no silent no-ops: a session that quietly forgets its anchor produces a fresh reroll wearing the language of an edit, which is the exact failure issue #336 calls out.

_ensure_session_column sync complexity: simple (2)

def _ensure_session_column(conn: Any) -> None

Add image_jobs.session_id if absent. Deferred rather than written into the .sql file because ALTER TABLE has no IF NOT EXISTS form in SQLite, and the migration must stay re-runnable — the same pattern image_jobs._ensure_queue_columns uses. Deliberately unguarded: callers reach this only after image_jobs._ensure_db has created the table, so a failing PRAGMA means the schema is broken. Swallowing it would skip the column and surface later as an inscrutable "no such column: session_id" on the first insert.
