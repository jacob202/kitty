Overview

Signal store — one append table for connector and system events (P1). A signal is a timestamped event from a connector or internal system: "mail received", "PR check failed", "monitor tripped", "nudge fired". Connectors emit signals; consumers (triage, the state composer, the brief) read them. A signal is never mutated except to be marked processed. Payloads carry summaries and pointers, not blobs — anything over MAX_PAYLOAD_BYTES is rejected so the table cannot silently absorb message bodies or documents. Public API: emit(source, kind, payload=None, dedupe_key=None, ts=None) -> dict | None Append one signal. Returns the stored record, or None when dedupe_key already exists (a duplicate from a re-polling connector is expected behaviour, not an error). list_recent(limit=50, source=None) -> list[dict] list_unprocessed(limit=50) -> list[dict] list_since(ts, limit=50) -> list[dict] count_unprocessed() -> int mark_processed(signal_id) -> bool
