Source: gateway/provider_prefs.py · Python · 5 functions · 0 classes

Overview

Which provider Kitty tries first, and which ones it skips entirely. The fallback chain used to be a hardcoded tuple, so changing it meant editing Python. This stores Jacob's preference in ``config/providers.json`` and merges it against the live provider table on every read — a provider that disappears from the table drops out of the saved order rather than breaking the chain, and a newly added one lands at the end instead of vanishing. Public API: load_preferences() -> dict save_preferences(order, disabled, *, known, active="auto") -> dict resolve_order(known, default_order) -> list[str] active_provider() -> str | None is_disabled(name) -> bool

def load_preferences() -> dict[str, Any]

Read the saved preference. A missing or corrupt file means 'no preference'. Corruption is logged rather than raised: a bad preference file must not be able to take the whole LLM chain down.

def save_preferences(order: Iterable[str], disabled: Iterable[str], known: Iterable[str], active: str = 'auto') -> dict[str, Any]

def resolve_order(known: Sequence[str], default_order: Sequence[str]) -> list[str]

Effective try-order: saved preference first, then anything it didn't mention. Disabled providers are excluded. Names in the saved order that are no longer in the table are dropped.
