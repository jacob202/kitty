# kitty-studio-r5-acceptance — make it, keep it, find it, use it

**Initiative:** kitty-studio-r5-v1
**Owner:** builder, once builder-frontend-proof-v1 has landed. Interactive before that.
**Depends on:** kitty-studio-r5-proto, kitty-studio-r5-image, kitty-studio-r5-library
**Free or paid:** free

## What Jacob can do after this

Trust the loop: make something, keep it, find it later, and use it — proven to
still work on the laptop and the phone, in both themes, after a reload.

## Why this is the next thing

R5-00 through R5-02 each prove one surface. The reason Image Lab and Library
exist together is the loop between them, and no test currently walks it.

This is also the packet where R-5 earns its acceptance record. The brief is
explicit that the redesign is not accepted from screenshots, and the repository's
merge policy requires a product acceptance record from someone who did not write
the change. A journey spec is what makes that reviewable by an agent driving the
real app rather than by a person forming an impression.

## Plan

1. Write the loop spec: start in Chat, make something in Image Lab, keep the
   result, find it in Library, bring it back into work. Assert the same artifact
   identity at every hop — that identity surviving is the actual claim.
2. Reload partway through and assert the identity again. State that survives
   navigation but not reload is the failure this catches.
3. Run it in both themes and under both viewport projects, matching how the
   repository already runs every spec.
4. Assert the mechanical invariants: no horizontal page overflow at iPhone-class
   widths, and a degraded retrieval source keeping context plus a next action.
5. Follow the existing smoke conventions: route-stub the gateway calls the spec
   needs, answer `**/proxy/health` or the app never mounts, set
   `localStorage['kitty-onboarded'] = 'true'` before navigating, and scope
   `getByRole('alert')` to `main`, because Next's route announcer is also an alert.

## Not in scope

Changing any surface to make the spec easier to write — if it is hard because the
product is wrong, that is a finding. Adding image or retrieval capability.
Re-proving what R4-03 already covers for Home and Chat.

## Verification

**Tier 1 — mechanical.**

```
cd gateway/kitty-chat && npx vitest run tests/ImageLabLayout.test.tsx tests/LibraryView.test.tsx --reporter=dot
cd gateway/kitty-chat && npx tsc --noEmit
```

These are the contracts from the two preceding packets and this one must not
regress them. Playwright stays out of Tier 1 on purpose: it needs a served app
and browser binaries, which a ten-minute sandboxed worker is a poor host for. It
belongs in Tier 2 where CI already runs `browser-smoke` across both projects.

**Tier 2 — running app.** This packet's whole product is the Tier 2 artifact: the
loop spec under `gateway/kitty-chat/tests/smoke/`, green under `desktop` and
`mobile`, in both themes, including the degraded case and the reload.

**Tier 3 — product acceptance.** R-5's acceptance record comes from here. A
reviewer who did not implement R-5 walks the loop in the running app and records
the evidence; an interactive agent session can do that against the real UI.
Publication and merge remain Jacob's decision.

## Stop condition

Stop and escalate if the artifact identity genuinely does not survive a hop or a
reload. That is a real defect with its own diagnosis and its own packet. Do not
weaken the spec until it passes — a journey test that was loosened to go green
gets cited later as proof the journey works, which is how a known defect becomes
an invisible one.

## Recovery

The spec is additive: delete it and the product is unchanged. If it exposes a
defect mid-packet, record the defect, leave the spec failing, and stop. A red test
with a written cause is a finished piece of work and a clean place for the next
session to resume.
