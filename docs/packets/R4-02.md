# kitty-studio-r4-chat — the conversation gets the room

**Initiative:** kitty-studio-r4-v1
**Owner:** builder, once builder-frontend-proof-v1 has landed. Interactive before that.
**Depends on:** kitty-studio-r4-proto, kitty-studio-r4-home
**Free or paid:** free

## What Jacob can do after this

Talk to Kitty on a screen that is mostly the conversation, with the related
context one disclosure away instead of crowding the thread.

## Why this is the next thing

The brief wants Chat quieter than Home: conversation dominant, and navigation,
artifacts, open loops and Builder handoff supporting it rather than competing.
Home and the shell land first because Chat inherits both the token contract and
the single-mascot rule from them; doing Chat earlier would mean doing it twice.

The constraint that matters most here is what *not* to build. The brief rejects a
separate mascot state machine and a second chat runtime outright, and the
existing `AssistantRuntimeProvider` already owns transport. So this packet is
layout and disclosure around an untouched runtime — which is also why it is
cheap, and why the test asserting exactly one runtime in the tree is the most
important line in it.

## Plan

1. Write the tests that freeze the hierarchy first: conversation is the flexible
   dominant region, the composer stays reachable, context can collapse, no
   permanent second column at narrow widths, and the mascot appears once rather
   than per message.
2. Recompose without touching transport. `KittyThread` and `InputBar` stay on the
   existing runtime provider; add presentation around them.
3. Add the desktop context rail as a filtered list of sections, where a section
   carries an availability flag and unavailable sections are filtered out before
   render. An absent source must collapse, never render an empty or invented
   card. On phone the same sections appear through one sheet.
4. Apply the Kitty voice to authored interface copy only — static helper, error
   and empty-state strings. Never post-process a model reply. Keep serious
   domains factual: the brief is explicit that medical, legal, financial and
   safety consequences keep the directness and drop the joking.
5. Keep raw technical detail behind disclosure rather than having Kitty make a
   joke about a failure nobody has diagnosed.

## Not in scope

The contextual mini-chat growing out of the mascot anchor — deferred by the
brief, and building it here creates the second chat system the brief bans. Image
Lab, which is R-5. Any change to chat transport, message storage or the runtime
provider. Rewriting model output.

## Stop condition

Stop and escalate if a context section cannot report its own availability
honestly — if the only way to know whether related artifacts exist is to render
the section and see. Guessing availability produces exactly the empty-or-fake
card the brief forbids, and the honest fix is a projection change, which is not
this packet.

## Recovery

Layout only; revert the changed components to `HEAD`. Because transport is
untouched, a failed attempt cannot lose a message or corrupt a thread — the worst
case is an ugly screen. Keep the hierarchy tests even if the layout reverts; they
are the durable part.
