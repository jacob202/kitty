**Owner:** builder
**Depends on:** kitty-release-r7-backup, kitty-release-r7-degraded
**Free or paid:** free

## What Jacob can do after this

Hand a backup proof to anyone — the command its own documentation prints
actually runs, and its pass verdict is about the same restore path
`./kitty backup` uses, not a legacy one.

## Why this is the next thing

`scripts/kitty_backup_proof.py` is the non-destructive evidence drill for owner
data. Two defects make its PASS cheaper than it reads:

- **The documented invocation does not run.** Its docstring says
  `python scripts/kitty_backup_proof.py` (`:9-11`); the script directory, not
  the repo root, lands on `sys.path`, so the import dies. Verified on current
  `main` (2026-09-17, `7dd703c7`):

```
$ python scripts/kitty_backup_proof.py
ModuleNotFoundError: No module named 'scripts'
EXIT=1
```

```
$ python -m scripts.kitty_backup_proof
...
VERDICT: PASS — restored replica matches pre-backup byte-for-byte
EXIT=0
```

- **It drills the wrong path.** `run_drill` calls `create_backup` and `restore`
  (`scripts/kitty_backup_proof.py:147-155`) on a replica whose manifest has no
  `mode`, so the restore takes the legacy branch
  (`scripts/kitty_backup.py:398-403`). `./kitty backup` writes an owner-data
  archive (`"mode": "owner-data"`), which restores through
  `restore_owner_backup` — a different function, with the Builder-quiescence
  gate and per-store integrity checks. The proof script's PASS is evidence for
  a path the product does not use. That is `REVIEW.md`'s "a claim of completion
  not backed by what ran", in the artifact whose whole job is that claim.

This packet does not change what a backup is; it makes the proof run and makes
it prove the real thing. It follows `kitty-release-r7-backup` in the sequence
because the routes are the consumer a proof drill serves, and both packets write
under `tests/`.

## Plan

1. Write the failing test first: `tests/test_backup_proof_script.py` runs the
   documented command as a subprocess from the repository root (path derived
   from `__file__`, not the current directory), asserts exit code 0, and asserts
   the output names the owner-data mode it proved. Today that subprocess exits 1
   with the quoted `ModuleNotFoundError`, so the test fails for the real reason.
2. In `scripts/kitty_backup_proof.py`, add the repo-root `sys.path` bootstrap
   used by `scripts/kitty_reliability_gate.py:17-19` so the documented
   invocation works.
3. Make `run_drill` exercise the owner-data path: seed a project root holding
   its canonical `data/kitty/kitty.db`, call `create_owner_backup`, assert the
   published manifest has `"mode": "owner-data"` and print that mode, wipe the
   replica to simulate data loss, restore with the owner-data path, and compare
   snapshots exactly as the drill does today. Keep the exit-code contract: 0 on
   a byte-identical restore with clean SQLite, 1 with every mismatch printed.
4. Keep the drill under a temp directory only. It must never read or write the
   live `data/` root and must never interfere with a running Builder.
5. Do not print model, provider or secret material; the manifest already records
   `excluded_secrets` and the drill only reports file names and diffs.
6. Run the gate and the script itself once more by hand, then paste both results
   into the packet's completion evidence.

## Not in scope

Adding backup capability (that is `kitty-release-r7-backup`). The HTTP routes.
A restore command that writes the live data root — restore stays behind the
existing CLI guard. Anything under `gateway/`: this packet edits one existing
script and adds one test file. This packet edits existing files only and creates
no new production files.

**Tier 2 — running app.** Not applicable: nothing serves this script and no

**Tier 3 — product acceptance.** Not triggered: no native UI source changes. The
only person-visible output is the script's own report; it prints the mode it
proved and file names and diffs, never model, provider or secret material, and
the exit code is tied to a comparison it actually ran.

## Stop condition

Stop and escalate if drilling the owner-data path would require creating a live
archive under the real backup root — the drill's contract is a scratch replica,
and weakening it to prove this packet is the failure the packet exists to
remove.

## Recovery

Revert `scripts/kitty_backup_proof.py` to `HEAD`; `tests/test_backup_proof_script.py`
stays red and expressive. The drill writes only inside `tempfile.mkdtemp()` and
cleans nothing up on success, so a failed attempt leaves only OS temp
directories.
