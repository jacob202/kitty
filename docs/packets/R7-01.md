# kitty-release-r7-backup — owner data can be backed up and verified from the product

**Initiative:** kitty-release-r7-v1
**Owner:** builder
**Depends on:** kitty-release-r7-degraded
**Free or paid:** free

## What Jacob can do after this

Ask Kitty to back up his data and to prove the backup restores, and get a plain
answer either way — without opening a terminal to run `./kitty backup`.

## Why this is the next thing

The hard part already exists and is tested. `scripts/kitty_backup.py` classifies
owner data, refuses to publish without the canonical personal database
(`create_owner_backup`, `scripts/kitty_backup.py:159-227`), moves an existing
target aside rather than deleting it, and verifies every restored SQLite file
with `PRAGMA integrity_check` (`restore_owner_backup`, `:230-348`). The CLI is
wired (`kitty:1028-1043`) and `tests/test_kitty_backup.py` passes 22 tests.

What is missing is every path that is not the terminal:

- **No gateway route touches it.** `rg -n "kitty_backup|create_owner_backup" gateway/`
  finds nothing outside tests. Verified directly on current `main`
  (2026-09-17, `7dd703c7`):

```
$ python -c "from gateway.routes import backup"
ImportError: cannot import name 'backup' from 'gateway.routes'
```

- **No UI exists.** `rg -rin "backup" gateway/kitty-chat/src` returns nothing,
  and `docs/session-notes/2026-09-03-worktree-salvage.md:8` records the same
  fact for the unlanded draft `docs/packets/KT-BACKUP-UI-01.md`.

`docs/ROADMAP.md`'s Phase 4 exit puts it plainly: owner data can be backed up
and restored **without a terminal**. This packet delivers the reachable half —
create, list and verify. The destructive restore command stays behind its
existing CLI guard; that is deliberate, not an omission.

## Plan

1. Write the failing tests first: `tests/test_backup_routes.py` importing
   `gateway.routes.backup` (today `ImportError`), covering create → list →
   verify against a temp project root and a temp backup root, plus the refusal
   and traversal cases below. Use `tmp_path` only; no test may touch the live
   data root.
2. Add `gateway/routes/backup.py`:
   - `GET /backup/owner` — list archives under the configured backup root by
     reading each `backup_manifest.json`; return id, created time, mode, copied
     file count, missing stores and size. Never return the filesystem root.
   - `POST /backup/owner` — call `create_owner_backup` through
     `asyncio.to_thread`; return the new archive in the same shape. A refusal
     (no personal database, destination exists) becomes a 409 whose `detail` is
     one plain sentence; the technical cause stays in the log.
   - `POST /backup/owner/{archive_id}/verify` — restore the named archive into a
     fresh scratch directory with the existing restore path so SQLite
     integrity_check runs, then delete the scratch copy. Return
     `{"ok": true, "files_checked": n}` or `{"ok": false, "reason": "..."}`; a
     failure is a result, not a 500.
   - Match `archive_id` against the listed archives and reject anything else
     with a 404 before it can be used to build a filesystem path.
3. Register the module in `gateway/routes/register.py` alongside the others.
4. Do not add a restore route. Restore mutates live data; it stays behind the
   CLI's existing explicit command until an interactive confirmation surface
   exists, which is frontend work this packet does not do.
5. Run the gate: both test files together.

## Not in scope

A Backup button or any UI (the frontend half of `KT-BACKUP-UI-01` remains
interactive work). Restoring from the product. The proof drill's own defects —
its documented invocation that does not run and its legacy-path drill — are
`kitty-release-r7-prove`, the packet that depends on this one; this packet does
not touch `scripts/`. The legacy `sync/export` + `sync/import` pair is **not**
the backup path and still carries the defects recorded in `KT-RESTORE-01`:
capped exports (`gateway/storage_sync.py:55,59`), a `{}`-returning preferences
stub (`:113-115`), append-not-replace importers (`:147-193`) underneath a
docstring that promises replacement (`:454-457`). That is a separate verified
finding, recorded here so it is not mistaken for this packet's subject; it is
not activated by it. This packet edits `gateway/routes/register.py` and creates
files only under `gateway/routes/` and `tests/`.

## Verification

**Tier 1 — mechanical.**

```
python -m pytest -q tests/test_kitty_backup.py tests/test_backup_routes.py
```

Today the command exits 4: `tests/test_backup_routes.py` does not exist yet and
is inside this packet's fence. The quoted `ImportError` is the defect the new
file pins. After the change both files pass, and `tests/test_kitty_backup.py`
passes **unchanged** — the fence that no backup semantics were rewritten.

The two standing criteria this packet carries: a refused or failed request
returns one plain sentence as its primary message (no stack trace, port,
environment variable name or absolute file path), and a verify result says pass
only after the named archive was actually restored and its SQLite files passed
integrity check. Nothing in this packet changes a control or a layout, so the
control-completeness and overflow criteria do not apply.

**Tier 2 — running app.** No UI source changes; existing browser-smoke specs
must still pass. The product check when a caller exists: create a backup from
the route, see it listed, verify it, and see the plain refusal when the personal
database is absent.

**Tier 3 — product acceptance.** Not triggered by native UI source; the
terminal-free journey is only half-visible until the Backup surface lands, and
that is explicitly out of scope.

## Stop condition

Stop and escalate if verify cannot be done without touching the live data root —
restoring in place to check a backup would risk the data the backup exists to
protect. If a scratch restore is impossible with the existing functions, the
drill design is wrong and belongs to Jacob, not to a worker's guess.

## Recovery

Revert `gateway/routes/backup.py` and `gateway/routes/register.py` to `HEAD`;
nothing durable was written outside temp directories. `tests/test_backup_routes.py`
stays as the red contract. A create that succeeded before the revert left an
archive under the backup root; archives are additive, the route never deletes
one, and removing one is a manual decision.
