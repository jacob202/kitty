### Row 4 would install a false-green gate

`make codegraph-check` prints a warning and **always exits 0**:

```
$ make codegraph-check
WARNING: codegraph index not initialized. Run: codegraph init
exit=0
```

Wiring that into CI as specified adds a check that passes whether or not the
index is fresh — precisely the failure mode rule **G2** in
`docs/FREE_MODEL_PACKET_STANDARD.md` exists to prevent ("a gate that would pass
even if the work were never done is worse than no gate, because it manufactures
false evidence").

The row is not merely unfinished; the specification is defective. Correct
sequence is to make the target exit non-zero on a missing or stale index
*first*, and only then wire it into a workflow.

### Why neither row is a `free-exec` candidate

- **Row 4** changes a CI workflow. The standard disqualifies dependency,
  lockfile, CI, and auth changes from unattended free execution — a free model
  editing the gate definitions can break every gate at once. It also requires
  deciding the staleness policy (fail vs warn, and at what age), which is an
  unresolved design decision.
- **Row 5** requires selecting "2 stable fixtures … packets that have been
  validated by prior workers." Choosing which packets qualify is judgement, and
  a free model will choose confidently and wrongly.
- **Row 6** is explicitly conditional on a judgement about whether the work is
  structural.

**Disposition:** step 3 of the conversion order yields no `free-exec`
candidates. Rows 4 and 5 are `paid-author`; row 4 additionally needs its
specification corrected before authoring. The `free-exec` packets already
proven in `ktf-001-free-exec-v1` remain the only verified ones.
