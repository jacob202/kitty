# kitty-studio-r4-home — Home stops being a dashboard

**Initiative:** kitty-studio-r4-v1
**Owner:** builder, once builder-frontend-proof-v1 has landed. Interactive before that.
**Depends on:** kitty-studio-r4-proto
**Free or paid:** free

## What Jacob can do after this

Open Kitty and see where he was, what actually needs him, and what else is still
alive — without an empty calendar card, a healthy-system card or a made-up photo
taking up the screen.

## Why this is the next thing

The brief gives Home four questions to answer: where was I, what needs me, what
else is alive, what can Kitty help with now. It also bans the things Home
currently does anyway — permanent empty Calendar and System cards, equal-weight
rounded rectangles, and decorative imagery invented to make a card look rich.

That last one has a named failure in the brief: `Continue where you left off`
must not invent a laptop, desk, truck, city or project photo on each load. That
is why this packet has a fixture supplying no media and an assertion that no
image element renders at all. A rule against invented pictures is only real if a
test fails when one appears.

## Plan

1. Write the sparse and dense fixtures first, and let them fail. Sparse proves
   absence: empty Calendar, healthy System, no Image Lab activity and a weak
   continuation must all produce *no module*, not an empty one. Dense proves the
   opposite: Continue, Needs You and Open Loops all readable and actionable at
   once.
2. Add the Ask Kitty input to Home. It owns local draft text and nothing else,
   delegating through the existing `onPromptSelect(text)` callback. Do not
   duplicate `InputBar`'s runtime, model or upload state — that is how a second
   chat system gets built by accident.
3. Convert the existing Home sources into conditional modules using the queries
   that already own them. `WhatsNext` becomes Continue when confidence is
   sufficient; `NeedsYou` stays authoritative; active Projects present as Open
   Loops.
4. Enforce truthful media at the component boundary: render an image only when a
   canonical projection supplies one, and otherwise render interface state.
5. Give the modules different anatomy on purpose. Continue is a rich resumable
   region, Needs You a sticky attention stack, Open Loops a compact cluster,
   Builder a progress surface, weather header chrome. The test asserts they do
   not all share one wrapper.

## Not in scope

Chat layout (R4-02). Image Lab, which is R-5. Any new Home store, projection or
query ownership — every module here reads something that already exists. Changing
what Builder reports; only how Home presents it, and the brief requires the Home
card to speak plain language rather than provider or database terms.

## Verification

**Tier 1 — mechanical.**

```
cd gateway/kitty-chat && npx vitest run tests/HomeState.test.tsx tests/HomeView.test.tsx tests/HomeStudioComposition.test.tsx --reporter=dot
cd gateway/kitty-chat && npx tsc --noEmit
```

`tests/HomeStudioComposition.test.tsx` is new and inside the fence. Today the
command fails on the missing file. `tests/HomeState.test.tsx` and
`tests/HomeView.test.tsx` exist and pass now, so any failure there after this
packet is a regression this packet caused.

If roughly 650 rendering tests fail with `React.act is not a function`, that is an
exported `NODE_ENV=production` in the shell, not this packet — the fix is already
written in `.worktrees/fix-ui-test-env-20260916`.

**Tier 2 — running app.** A smoke spec covering Home with sparse and dense state,
proving conditional modules actually disappear in a browser rather than only in
jsdom. CI runs it across the `desktop` and `mobile` projects.

**Tier 3 — product acceptance.** User-facing, so a reviewer who did not implement
it completes the task in the running app and records the evidence; an interactive
agent session can do this. Publication stays Jacob's decision.

## Stop condition

Stop and escalate if answering any of Home's four questions truthfully requires a
projection that does not exist yet. Inventing the data is the one failure the
brief cares most about, and a missing projection is a real finding worth a
separate packet — not something to paper over with a plausible-looking card.

## Recovery

Presentation-layer only; revert the changed components to `HEAD` and re-run. The
fixtures are worth keeping even if the composition is reverted: they encode the
sparse and dense contracts and cost nothing to carry. If the packet half-lands,
prefer reverting the composition and keeping the tests red over leaving Home in a
state where some modules are conditional and others are not.
