# kitty-studio-r5-library — finding it again is the whole point

**Initiative:** kitty-studio-r5-v1
**Owner:** builder, once builder-frontend-proof-v1 has landed. Interactive before that.
**Depends on:** kitty-studio-r5-proto, kitty-studio-r5-image
**Free or paid:** free

## What Jacob can do after this

Find something he made or saved weeks ago and put it straight back into what he
is doing now — and when the search is having a bad day, see that plainly instead
of an empty page.

## Why this is the next thing

Library is the recall half of the same loop Image Lab starts. Making things is
worthless if they cannot be found, and the integration decision on record is that
Library is Artifact-backed recall and reuse rather than a second store.

The part that usually goes wrong is degradation. Retrieval has several sources
and they fail independently, so the honest states are not "results" and "no
results" but "results", "nothing matched", and "one source is down and these
results are therefore incomplete". Flattening the third into the second is a lie
the standard explicitly forbids: nothing reports state it did not measure.

`docs/packets/OK-LIBRARY-01.md` describes the ingest-to-reuse contract and is an
unactivated draft. This packet does not re-derive or activate it, and adds no
index or search capability.

## Plan

1. Assert the reuse path end to end in the component test first: a real artifact
   opens from Library and reaches chat through the existing artifact contract.
   That is the packet's reason to exist, so it is the first thing proven.
2. Make the degraded case explicit. A source that is down renders the context
   that *is* available plus the next useful action, never a bare error string and
   never a silent empty state.
3. Keep the indexed and unindexed distinction visible. If a result was found
   without the index, say so rather than presenting both as equivalent.
4. Render interface state for an artifact with no preview — strong typography,
   real metadata, tags, actions. No placeholder, no stock image.
5. Touch no authority. The existing artifact gateway tests passing unchanged is
   the assertion that no second store, index or search path appeared.

## Not in scope

Improving retrieval quality, adding a search backend, or changing indexing. Image
Lab, which is R5-01. Any new artifact type. If retrieval genuinely cannot report
which source degraded, that is a finding for a backend packet, not something to
approximate in the component.

## Verification

**Tier 1 — mechanical.**

```
cd gateway/kitty-chat && npx vitest run tests/LibraryView.test.tsx tests/ArtifactChatCard.test.tsx tests/artifactGateway.test.ts tests/library-chat-001.test.tsx --reporter=dot
cd gateway/kitty-chat && npx tsc --noEmit
```

All four exist and pass today. `tests/artifactGateway.test.ts` is the authority
fence — if it fails after this packet, something introduced a second path to
artifacts and the packet has exceeded its scope.

A note from this file's own history, recorded in the packet standard as failure
F3: `LibraryView.test.tsx` once carried two tests that contradicted each other
and a third that contradicted the packet's acceptance criterion, and CI caught it
rather than the author. When adding cases here, check them against each other
before running them.

**Tier 2 — running app.** A smoke run covering find, open and use, plus one
degraded source, across both viewport projects.

**Tier 3 — product acceptance.** User-facing; a reviewer who did not implement it
finds an artifact and uses it in the running app, then records the evidence. An
interactive agent session can do that. Merge stays Jacob's decision.

## Stop condition

Stop and escalate if the degraded state cannot be distinguished from the empty
state with the information Library actually receives. Presenting "we found
nothing" when the truth is "we could not look" is the failure this packet is
built to prevent, and shipping it would be worse than shipping nothing.

## Recovery

Presentation only; revert the changed components to `HEAD`. The degraded-source
fixture is worth keeping regardless — it is the hard part to write and the easy
part to lose.
