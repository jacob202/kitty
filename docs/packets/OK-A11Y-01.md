# OK-A11Y-01 — Accessibility Closure for Primary Journeys

**Status:** draft candidate; not activated
**Roadmap phase:** 5 — precision/accessibility/brand

## Mission
Close accessibility defects that visual polish alone cannot catch so primary Kitty workflows remain understandable and operable across keyboard, assistive semantics, motion preferences, text scaling, contrast and touch.

## Depends on
- `OK-PRECISION-01` and enough surface precision migrations that shared primitives exist.
- `OK-RESPOND-01` for consistent interaction states.

## Product acceptance moment
A reviewer can complete the primary journey on each rail surface without a pointer where practical, follow sensible focus order, understand controls/states from accessible names, zoom/text-scale without losing actions, enable reduced motion, and never rely on color alone to understand status.

## Required behavior
- Interactive elements have correct semantics and concise accessible names; div-click targets do not masquerade as controls.
- Focus order follows visual/task order; dialogs/sheets trap and restore focus correctly.
- Primary workflows work by keyboard on desktop; visible focus is never suppressed.
- Async state changes that matter are announced without noisy repeated live regions.
- Status/error/success meaning is never color-only; contrast is acceptable in supported light/dark themes.
- Reduced motion removes nonessential transitions/animation without hiding state change.
- 200% browser zoom / larger text does not clip/obscure primary controls or create document-level horizontal scroll in supported layouts.
- Persistent phone controls meet the shared 44px target.

## Verification
**Tier 1:** component tests for roles/names/focus/reduced-motion hooks plus automated accessibility checks already supported by the stack; add only lightweight tooling if it materially improves proof and does not become a framework project.

**Tier 2:** desktop keyboard-only pass and phone-class large-text/zoom/reduced-motion pass across Home, Chat, Work, Projects, Image Lab, Library, Automations, Settings.

**Tier 3:** independent reviewer records primary-journey accessibility acceptance and exact remaining limitations.

## Non-goals
- Formal public compliance certification.
- Accessibility statement/legal process.
- Redesigning domain workflows solely to satisfy an automated score.

## Done when
No known accessibility blocker prevents the primary supported journeys, and the shared primitives make regressions harder to reintroduce.
